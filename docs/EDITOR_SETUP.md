# Сборка вертикального среза в редакторе Unity — пошагово

Весь код уже написан и лежит в `Assets/_Project/Scripts`. Но сцены и связи
между компонентами в инспекторе (какая ссылка куда перетащена) Unity
хранит не как текст, который можно надёжно сгенерировать снаружи, — это
нужно сделать руками в редакторе. Префабы мини-игр раньше тоже нужно было
собирать руками (десятки кликов), но теперь для них есть кнопка — см.
раздел 3. Ручная сборка префаба всё равно описана в Приложении A в конце
документа — пригодится, когда в проекте появится новый, третий тип
мини-игры, для которого такой кнопки ещё не будет.

Не обязательно проходить всё за один присест. Если что-то не совпадает
с тем, что видите на экране, или Unity показывает ошибку — сохраните,
опишите (лучше со скриншотом), и разберёмся.

## 0. Установка Unity

1. Скачать и установить **Unity Hub**: https://unity.com/download
2. В Hub: `Installs` → `Install Editor` → найти **Unity 6.3 LTS**
   (номер сборки начинается с `6000.3.`). Если в списке по умолчанию нет —
   вкладка `Archive` на unity.com/releases позволяет найти конкретную
   версию и открыть её напрямую через Hub.
3. При установке редактора отметить модуль **Microsoft Visual Studio
   Community** (если на компьютере ещё нет IDE для C#) и **Windows Build
   Support (IL2CPP)**. Шаблон 2D/3D выбирается позже, при создании
   проекта, — не на этом шаге.
4. Установка займёт время (несколько ГБ) — можно продолжать читать дальше.

### 0.1 Переключить интерфейс Unity на английский (сделать один раз, сразу)

Весь этот документ, вся официальная документация Unity, все видео-туториалы
и форумы используют английские названия меню. Если оставить интерфейс
русским, названия на экране не будут совпадать с тем, что написано здесь
(и в любом другом источнике) — придётся всё время гадать/переводить
обратно. Проще один раз переключить:

1. Откройте проект (см. пункт 1 ниже — можно вернуться к этому шагу сразу
   после открытия).
2. Верхнее меню (по-русски сейчас) → **Правка** → в самом низу списка —
   **Настройки** (или **Preferences**, если уже частично на английском).
3. В открывшемся окне слева список разделов — найдите **Языки** (обычно
   ближе к верху списка).
4. Справа появится выпадающий список, сейчас в нём выбрано **Русский** —
   откройте его и выберите **English**.
5. Закройте окно настроек. Может попросить перезапустить Unity — если да,
   закройте и откройте заново через `OpenInUnity.bat`.

Дальше по всему документу меню называются по-английски — после этого шага
они будут совпадать с тем, что на экране.

### 0.2 Из чего состоит окно Unity

Если вы впервые открываете Unity, вот на что смотреть (расположение может
чуть отличаться, но сами панели есть всегда — их видно по подписи на
вкладке каждой панели):

- **Hierarchy** (обычно слева) — список всех объектов текущей открытой
  сцены. Правый клик по пустому месту здесь → создание нового объекта.
  Правый клик по существующему объекту → создание нового объекта ВНУТРИ
  него (то есть новый объект станет его "ребёнком" — в списке это видно
  по отступу).
- **Scene** (по центру, самая большая панель) — визуальный вид сцены.
- **Game** (вкладка рядом со Scene, сверху панели) — как будет выглядеть
  игра при нажатии Play.
- **Inspector** (обычно справа) — свойства того объекта, который сейчас
  выделен (кликнут) в Hierarchy или в Project. Кнопка **`Add Component`**
  в самом низу Inspector — именно так на объект добавляются скрипты и
  компоненты.
- **Project** (обычно внизу) — все файлы проекта на диске: папки, скрипты,
  префабы, сцены, ассеты. Слева в этой панели — дерево папок, справа —
  содержимое той папки, что сейчас выбрана слева.

Если какой-то из этих панелей не видно на экране: `Window → General →`
и выбрать её по названию (например `Window → General → Hierarchy`) —
откроет/вернёт её. Если весь экран выглядит непривычно (панели не там, где
на скриншотах) — `Window → Layouts → Default` вернёт стандартное
расположение всех панелей разом.

Два действия, которые дальше встречаются постоянно:

- **«Добавить компонент X»** = выделить объект в Hierarchy → в Inspector
  внизу нажать `Add Component` → напечатать название → кликнуть по
  найденному результату в списке.
- **«Перетащить X в поле Y»** = навести курсор мыши на X (объект в
  Hierarchy или файл в Project) → зажать левую кнопку мыши → не отпуская,
  переместить курсор на поле Y (обычно в Inspector) → отпустить кнопку
  мыши. Если всё получилось, в поле появится имя X.

## 1. Открытие проекта

Проект живёт в `C:\UnityProjects\Game` — обычной локальной папке, **не**
внутри `OneDrive`. Это важно: изначально проект лежал в
`OneDrive\Desktop\Game`, и это привело к тому, что Unity Hub не находил
проект и/или не мог сохранить сцену — OneDrive пытается синхронизировать
десятки тысяч мелких служебных файлов Unity и блокирует их прямо в момент
записи. Если на этом компьютере включён "Known Folder Move" (сам Рабочий
стол/Документы редиректнуты в OneDrive — как в нашем случае), под новые
Unity-проекты нужна папка вне этого дерева, например `C:\UnityProjects\...`.

Папка `Game` уже содержит `Assets/_Project` с кодом, `ProjectSettings/`,
`Packages/`, `.git` и документацию — то есть это уже полностью готовый,
валидный Unity-проект, просто нужно его открыть, ничего создавать не
нужно:

- Самый надёжный способ — двойной клик по [`OpenInUnity.bat`](../OpenInUnity.bat)
  в корне проекта. Он запускает нужную версию редактора сразу на этой
  папке в обход Unity Hub (Hub у нас периодически глючил с обнаружением
  проектов).
- Либо через Unity Hub: `Projects` → стрелка рядом с `Open` → `Add project
  from disk` → выбрать `C:\UnityProjects\Game` (зайти внутрь папки, чтобы
  в окне были видны `Assets`, `Packages`, `ProjectSettings`, и только
  тогда нажать «Выбрать папку») → открыть из списка.

Первое открытие после переноса займёт несколько минут — Unity заново
импортирует всё и создаёт служебную папку `Library/`.

**Важно:** открывайте проект только ОДНИМ способом за раз и не запускайте
второй раз, если первое окно уже открыто (даже если кажется, что оно
зависло или потерялось за другими окнами — проверьте панель задач/Alt+Tab
сначала). Два запущенных редактора на одной и той же папке проекта
конфликтуют друг с другом за файлы и дают самые странные на вид ошибки.

## 2. TextMeshPro

Почти весь текст в проекте использует TextMeshPro (TMP) — более гибкий
инструмент текста, чем старый Unity `Text`. Ему нужен один набор файлов
("Essential Resources"), который не ставится вместе с Unity автоматически,
а импортируется по кнопке. Сделайте это сейчас, одним из двух способов:

**Способ А (через меню, надёжнее):**

1. В самом верху экрана — строка меню: `File`, `Edit`, `Assets`,
   `GameObject`, `Component`, `Window`, `Help`.
2. Нажмите **`Window`**.
3. В выпадающем списке найдите **`TextMeshPro`** (обычно ближе к низу
   списка) → наведите на него, появится ещё один список сбоку.
4. В нём нажмите **`Import TMP Essential Resources`**.
5. Появится небольшое окно **"Import Unity Package"** со списком файлов —
   внизу справа нажмите синюю кнопку **`Import`**.
6. Подождите, пока Unity импортирует (несколько секунд, в правом нижнем
   углу окна Unity будет крутиться индикатор прогресса).

**Способ Б (само выскочит):** если способа А не находите — просто
переходите к разделу 3 и запускайте кнопку сборки. При самой первой
попытке создать TMP-текст Unity сама покажет окно **"TMP Importer"** с
кнопкой **`Import TMP Essentials`** — нажмите её, подождите импорт.

## 3. Собрать всё одной кнопкой (префабы, тестовые уровни, три сцены)

Раньше здесь было руками: 4 префаба (~50 кликов) плюс три сцены (Boot,
Menu — самая большая, там больше 25 отдельных UI-элементов, — и Gameplay).
Вместо этого написан код, который делает всё то же самое сам:
`Assets/_Project/Editor/PrefabBuilderMenu.cs`, `SampleDataMenu.cs` и
`SceneBuilderMenu.cs`. Это не магия — обычные C#-скрипты, которые создают
те же объекты, добавляют те же компоненты и перетаскивают те же ссылки,
что раньше делались вручную мышкой, только из кода. Такие скрипты может
писать и запускать только сам редактор Unity ("инструменты редактора"), на
итоговую игру они не влияют — это не часть геймплея.

1. В самом верху экрана нажмите **`MathGame`** (если пункта нет — скрипты
   ещё не скомпилировались или в них ошибка, загляните в
   `Window → General → Console`, нет ли там красных сообщений).
2. Нажмите **`0. Build Absolutely Everything`** — самый первый пункт.
3. Если сейчас открыта сцена с несохранёнными изменениями — Unity спросит,
   сохранить ли их перед продолжением (жмите «Сохранить и продолжить»,
   ничего не потеряется).
4. Подождите несколько секунд. В окне **Console** должна появиться
   цепочка сообщений `Готово: ...` — по одному на префабы, тестовые
   уровни и сцены, и в конце `Готово: префабы, тестовые уровни и все 3
   сцены собраны...`.

После этого в **Project** появятся все префабы (раздел выше про них уже
не нужен — пропускайте прямо к разделу 4) и в `Assets/_Project/Scenes/` —
`Boot.unity`, `Menu.unity`, `Gameplay.unity`, уже добавленные в Build
Settings в правильном порядке.

**Если вы уже вручную начали `Boot.unity`** (добавляли `GameServices` /
`Boot Loader`) — не страшно: инструмент пропускает любую сцену/префаб,
который уже существует на диске, и не трогает то, что вы уже сделали
руками. Если вы это ещё не доделали и не сохранили — просто нажмите
`Ctrl+S` перед запуском кнопки, а если хотите, чтобы инструмент собрал
`Boot.unity` тоже сам с нуля, — удалите файл `Boot.unity` перед запуском.

Отдельные шаги (`1. Build Prefabs`, `2. Bootstrap Sample Level Data`,
`3. Build Scenes`) в том же меню — то же самое по частям, на случай если
нужно пересобрать что-то одно отдельно.

## 4. Первый запуск

1. Открыть сцену `Boot.unity` (если не открыта), нажать `Play`.
2. Ожидается: мгновенный переход в `Menu`, три кнопки главного экрана.
3. `Играть` → сетка из 2 уровней (уровень 1 доступен, уровень 2 пока
   заблокирован — так и должно быть, пока уровень 1 не пройден).
4. Открыть уровень 1 → должны появиться герой и 2 голема с примерами.
   Клик по голему с ответом ≤ силы героя → победа, герой поглощает силу и
   т.д. до конца всех трёх башен (2→3→4 голема).
5. После победы — экран результата, кнопка «Следующий уровень» ведёт на
   уровень 2 (двери).
6. `Esc` в любой момент внутри уровня → меню паузы.
7. `Настройки` из главного меню → все переключатели должны отражать
   реальные значения и сохраняться (проверить: поменять диапазон чисел,
   выйти в меню и зайти в настройки снова — значение должно остаться).

Внешний вид пока минимальный (плейсхолдер-квадраты, простые кнопки без
стиля) — это ожидаемо, вёрстка/арт добавляются позже. Главное сейчас —
чтобы всё работало функционально. Если что-то не работает — пришлите
текст ошибки из консоли Unity (`Window → General → Console`) или
скриншот, разберёмся вместе.

## Приложение A: как собран префаб вручную (для справки)

Раздел 3 выше собирает эти префабы кодом за секунду. Это приложение — то,
что раньше было основной инструкцией: пошагово, что код в разделе 3 делает
"руками". Пригодится, если: захотите понять, из чего вообще состоит
префаб (когда объясняете это преподавателю); нужно будет пересобрать
что-то после ручных правок; или в проекте появится новый тип мини-игры, у
которого такой кнопки-автосборщика ещё нет.

Открывать для сборки можно любую сцену — например `SampleScene`
(`Project → Assets → Scenes → SampleScene`, двойной клик). Это временная
рабочая площадка, в финальный проект сама сцена не входит.

### A.1 Префаб голема

1. Вверху экрана нажмите **`GameObject`**.
2. Наведите (не нажимайте) на **`2D Object`** — сбоку раскроется список.
3. В нём наведите на **`Sprites`** — раскроется ещё один список.
4. Нажмите **`Square`**.
   → В **Hierarchy** (слева) появится новый объект `Square`.
5. Дважды кликните по слову `Square` прямо в Hierarchy — оно станет
   редактируемым — сотрите и впишите **`Golem`**, нажмите `Enter`.
6. Кликните один раз по `Golem` в Hierarchy, чтобы выделить его — справа
   в **Inspector** появятся его свойства.
7. В самом низу Inspector нажмите кнопку **`Add Component`**.
8. Появится строка поиска — напечатайте **`Box Collider 2D`** и кликните
   по найденному варианту в списке под строкой поиска.
   (Без этого шага клик по голему в игре не будет работать — коллайдер
   это и есть "область, по которой можно кликнуть мышкой".)
9. Снова **`Add Component`** → напечатайте **`Golem View`** → кликните по
   найденному варианту. Это наш собственный скрипт; если он не находится
   в поиске — подождите немного (Unity ещё может компилировать скрипты,
   внизу справа экрана виден вращающийся индикатор) и попробуйте снова.
10. Теперь добавим текст с примером над голем. Кликните **правой** кнопкой
    мыши прямо по `Golem` в Hierarchy → в открывшемся меню наведите на
    **`3D Object`** → в боковом списке нажмите **`Text - TextMeshPro`**.
    (В этом же меню есть похожий пункт `Text - TextMeshPro` в разделе `UI`
    — он НЕ подходит, нужен именно из `3D Object`.)
    → Появится новый объект чуть правее и с отступом внутри `Golem` в
    Hierarchy — отступ означает, что он стал "ребёнком" голема.
11. Переименуйте этот новый объект (как в шаге 5) в **`ExpressionLabel`**.
12. С выделенным `ExpressionLabel` в Inspector найдите блок **`Transform`**
    (самый верхний) → строку **`Position`** → во второе число (`Y`) впишите
    **`1`** и нажмите `Enter` — текст сдвинется выше тела голема.
13. Кликните обратно по `Golem` (родителю) в Hierarchy, чтобы выделить его.
14. В Inspector найдите блок **`Golem View`** (добавили в шаге 9) — в нём
    видно пустое поле **`Expression Label`**.
15. Перетащите объект `ExpressionLabel` из Hierarchy на это поле: наведите
    курсор на `ExpressionLabel` в Hierarchy → зажмите левую кнопку мыши →
    не отпуская, переместите курсор на поле `Expression Label` в
    Inspector → отпустите кнопку. В поле должно появиться `ExpressionLabel`.
16. В окне **Project** (внизу экрана) откройте папку
    `Assets → _Project → Prefabs → Minigames → Towers` — кликайте по
    стрелочкам слева или дважды по папкам справа, пока не окажетесь внутри
    именно этой папки.
17. Перетащите `Golem` из **Hierarchy** в открытую область справа в окне
    **Project** (тот же приём: навести → зажать → перетащить → отпустить).
    Как только отпустите кнопку мыши — появится файл `Golem` с синей
    иконкой куба. Это и есть сохранённый префаб.
18. Объект `Golem` в Hierarchy теперь не нужен — кликните по нему правой
    кнопкой мыши → **`Delete`**. (Сам префаб при этом никуда не денется,
    он уже сохранён в Project.)

### A.2 Префаб TowerMinigame (герой + управляющий объект)

1. В Hierarchy кликните правой кнопкой мыши по **пустому месту** (не по
   объекту) → **`Create Empty`**.
   → Появится пустой объект с именем `GameObject`.
2. Переименуйте его (как в A.1.5) в **`TowerMinigame`**.
3. Выделите `TowerMinigame` кликом в Hierarchy → в Inspector →
   `Add Component` → напечатайте **`Tower Minigame Controller`** →
   кликните по найденному варианту.
4. Теперь добавим героя ВНУТРИ `TowerMinigame`. Правило Unity: новый
   объект создаётся внутри того, что сейчас выделено. Проверьте, что
   `TowerMinigame` сейчас выделен (подсвечен) в Hierarchy, и повторите
   шаги A.1.1–A.1.4 (`GameObject → 2D Object → Sprites → Square`).
   → Новый `Square` должен появиться с отступом под `TowerMinigame`. Если
   он появился БЕЗ отступа (то есть рядом, а не внутри) — перетащите его
   мышкой прямо на слово `TowerMinigame` в Hierarchy, это тоже сделает его
   дочерним.
5. Переименуйте этот `Square` в **`Hero`**.
6. С выделенным `Hero` в Inspector → `Transform` → `Position` → впишите
   `X = -2`, `Y = 0`, `Z = 0`.
7. На `Hero` → `Add Component` → напечатайте **`Hero View`** → выберите
   его. (Коллайдер герою добавлять не нужно — его не кликают мышкой.)
8. С выделенным `Hero` повторите шаги A.1.10–A.1.12: правой кнопкой по
   `Hero` → `3D Object` → `Text - TextMeshPro` → переименовать в
   **`PowerLabel`** → `Position Y = 1`.
9. Выделите `TowerMinigame` (родителя, не `Hero`) в Hierarchy → правой
   кнопкой по нему → **`Create Empty`** → переименовать в **`GolemSlots`**
   → `Position (0, 0, 0)`.
10. Кликните по `TowerMinigame` в Hierarchy, чтобы выделить именно его →
    в Inspector найдите блок **`Tower Minigame Controller`** — в нём
    несколько пустых полей. Заполните их перетаскиванием (приём из шага
    A.1.15):
    - **`Hero`** ← объект `Hero` из Hierarchy.
    - **`Golem Prefab`** ← файл `Golem` из окна **Project**
      (`Assets/_Project/Prefabs/Minigames/Towers/Golem` — НЕ из Hierarchy,
      там его больше нет, мы удалили его в A.1.18).
    - **`Golem Slot Parent`** ← объект `GolemSlots` из Hierarchy.
    - **`Hero Power Label`** ← объект `PowerLabel` из Hierarchy (он внутри
      `Hero` — если не видно, нажмите маленькую стрелочку слева от `Hero`
      в Hierarchy, чтобы развернуть список).
    - Остальные поля (`Golem Spacing`, `Tower Spacing`, `Approach Offset`,
      `Move Duration`) не трогайте — там уже стоят рабочие значения по
      умолчанию, их можно будет покрутить позже.
11. Перетащите `TowerMinigame` из Hierarchy в окно Project, в ту же папку
    `Assets/_Project/Prefabs/Minigames/Towers/` (как в A.1.16–A.1.17) —
    создастся префаб `TowerMinigame`.
12. Удалите `TowerMinigame` из Hierarchy (как в A.1.18, правой кнопкой →
    `Delete`) — префаб уже сохранён, в сцене он больше не нужен.

### A.3 Префаб двери

Ровно та же механика, что в A.1 — только другой скрипт и другие имена
объектов.

1. `GameObject` → навести на `2D Object` → навести на `Sprites` → нажать
   `Square` (как в A.1.1–A.1.4).
2. Переименовать в **`Door`** (двойной клик по имени в Hierarchy).
3. Выделить `Door` → Inspector → `Add Component` → **`Box Collider 2D`**
   (обязательно — без него клик по двери не сработает).
4. `Add Component` → **`Door View`**.
5. Правой кнопкой по `Door` в Hierarchy → `3D Object` → `Text -
   TextMeshPro` → переименовать в **`ExpressionLabel`** → `Transform →
   Position → Y = 1`.
6. Выделить `Door` обратно → в блоке **`Door View`** в Inspector два поля:
   - **`Expression Label`** ← перетащить `ExpressionLabel` из Hierarchy.
   - **`Door Renderer`** ← перетащить сюда сам объект `Door` из Hierarchy
     (да, тот же самый объект, на котором вы сейчас стоите, — у него есть
     свой компонент `Sprite Renderer`, это поле именно на него и
     ссылается; перетаскивать себя на своё же поле — нормально и работает).
7. В окне Project открыть `Assets/_Project/Prefabs/Minigames/Doors/`,
   перетащить туда `Door` из Hierarchy (создаст префаб), затем удалить
   `Door` из Hierarchy правой кнопкой → `Delete`.

### A.4 Префаб DoorMinigame (управляющий объект)

1. В Hierarchy правой кнопкой по пустому месту → `Create Empty` →
   переименовать в **`DoorMinigame`**.
2. Выделить `DoorMinigame` → `Add Component` → **`Door Minigame
   Controller`**.
3. (Необязательно, но для красоты сцены) с выделенным `DoorMinigame`:
   `GameObject → 2D Object → Sprites → Square` → переименовать в
   **`Hero`** — это просто декорация без скриптов, стоит на месте, никуда
   не двигается (в отличие от героя в «Башнях»).
4. С выделенным `Hero`: правой кнопкой → `3D Object → Text - TextMeshPro`
   → переименовать в **`HeroTargetLabel`** → `Position Y = 1`.
5. Выделить `DoorMinigame` (родителя) → правой кнопкой → `Create Empty` →
   переименовать в **`Doors`** → `Transform → Position → X = 2` (несколько
   впереди героя).
6. Выделить `DoorMinigame` → в блоке **`Door Minigame Controller`** в
   Inspector заполнить перетаскиванием:
   - **`Hero Target Label`** ← `HeroTargetLabel` из Hierarchy.
   - **`Door Prefab`** ← файл `Door` из окна **Project**
     (`Assets/_Project/Prefabs/Minigames/Doors/Door`).
   - **`Doors Parent`** ← объект `Doors` из Hierarchy.
   - **`Door Spacing`** — не трогать, значение по умолчанию рабочее.
7. Перетащить `DoorMinigame` из Hierarchy в
   `Assets/_Project/Prefabs/Minigames/Doors/` в окне Project (создаст
   префаб), удалить `DoorMinigame` из Hierarchy.
